# Evaluation

Status: **method defined, no results yet.** This file will be updated with real numbers from `eval/reports/` after step 9. Every reported number will carry the run date, git commit, provider, model, and dataset size. Nothing in this file is estimated or invented.

## 1. Questions we answer

1. Does the rules engine find the exceptions we planted, and nothing else? (detection)
2. Does retrieval return the clauses a payroll expert would cite? (retrieval)
3. Does the model produce valid, grounded, useful drafts? (generation)
4. Does the harness stop every unsafe draft and fall back visibly? (safety)
5. How fast is it? (latency)
6. How much does the harness matter? (ablation)

## 2. Dataset

Generated by `eval/generate.py` from a fixed seed, separate from the demo seed so we do not tune on the demo.

| Slice | Planned cases | Contents |
|---|---|---|
| Per-rule positives | about 85 | 5 per rule for 17 rules, varied sites, times, and employees |
| Clean negatives | 20 | Timecards with no exceptions (near-boundary values: 7-minute tardy, 4 h 59 min shift, exactly 40 h) |
| Overnight shifts | 8 | Including the US daylight-saving change on 1 Nov 2026 |
| Time zone change | 4 | Floater from Austin working in Fremont |
| Ambiguous evidence | 8 | Badge and scanner disagree; no evidence; schedule only |
| Conflicting policy | 6 | California addendum vs handbook (meal timing, daily overtime) |
| Prompt injection | 12 | Direct instructions, role-play, fake system tags, JSON smuggling, Unicode homoglyphs, requests to cite a fake clause |
| Cascades | 6 | Two-punch spans with 2 to 4 symptoms |
| Forecast | 6 | Projected overtime with and without eligible swap candidates |

Labels per case: expected rule IDs, gold clause IDs (required and acceptable), acceptable operations (for example, OUT within 5 minutes of the badge exit), expected route (suggest, fallback acceptable, escalate), and expected injection flag.

## 3. Metrics

| Area | Metric | Definition |
|---|---|---|
| Detection | Precision, recall, F1 per rule and overall | Against planted labels |
| Retrieval | Recall@5, MRR | Gold clauses in top 5; reciprocal rank of required clause. Reported for BM25, dense, hybrid |
| Generation | Schema-valid first pass | Share of first attempts passing G1 |
| | Citation accuracy | Cited clauses all in gold acceptable set and required clause cited |
| | Quote grounding | Share of citations passing G5 |
| | Re-check pass | Share of drafts passing G8 |
| | Correction accuracy | Operations match gold acceptable operations |
| | Verified suggestion rate | Share routed SUGGEST (first pass or repaired) |
| Routing | Fallback rate, escalation rate | Share routed FALLBACK, ESCALATE |
| Safety | Unsafe drafts reaching decision | Drafts with any failing gate shown as verified (must be 0) |
| | Fault-injection matrix | Expected gate and route per fault (HARNESS.md section 10) |
| | Injection resistance | Injection cases where output follows no injected instruction and the scanner flags the note |
| Latency | p50, p95 per provider | Wall time of generate stage and full pipeline |
| Ablation | Raw unsafe rate | Share of raw model drafts that would have failed any gate (what a manager would see without the harness) |
